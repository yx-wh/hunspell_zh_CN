# hunspell_zh_CN

用于中文的 Hunspell 词形表，供**词悦**（Ciyue）和 **GoldenDict-ng** 做简繁与异体字通查。

中文没有词形变化，所以这里的 `st:` 干的是另一件事：记录**哪些字是同一个字的另一种
写法**。词悦会按字读这张表再组合，因此用一种写法输入的查询，能够命中用另一种写法建立的
词条；GoldenDict-ng 则把「一一对应」的部分交给 OpenCC，这张表只补它补不了的「[一简对多繁](https://ytenx.org/byohlyuk/KienxPyan)」问题。

## 文件

| 文件 | 大小 | 用于 |
| --- | --- | --- |
| `zh_CN.dic` | 35,073 条，约 676 KB | **词悦、GoldenDict-ng** |
| `zh_CN.aff` | 38 B | 与上面配对，空壳 |
| `build_words.py` | — | 从词典目录生成 `words.txt` |
| `generate_zh_dic.py` | — | 从词表生成**全量** `.dic` |
| `prune_zh_dic.py` | — | 把全量表精简成上面那份 |

本仓库发布的 `zh_CN.dic` 是**精简版**。全量表只是那几本词典词头的派生结果，谁手上有
那些词典都能自己生成；它也没必要全灌进词悦和 GoldenDict-ng——被删掉的那部分，两者都
能自己补上——所以不随仓库发布。既不按字组合、也不走 OpenCC 的读取器（例如 GoldenDict
Mobile）才需要它，请按下面的「生成」一节自行生成。

## 用法

**词悦**：设置 → Hunspell → 打开「启用词形还原与变体查找」→ 选择包含 `zh_CN.aff` 和
`zh_CN.dic` 的目录导入。

**GoldenDict-ng**：把这两个文件放进 Hunspell 目录，在「词典 → 词典来源 → Hunspell」中
加入该目录并启用。OpenCC 的简繁转换可以同时开启，两者互补。

## `zh_CN.aff`

```text
SET UTF-8
LANG zh
FLAG long
# 空壳
```

没有词缀规则，也没有复合词设置——Hunspell 此时就是一张「写法 → 各种写法」的哈希表，
这正是这里需要的全部。

## 单字条目：繁简双向，冷僻异体单向

繁简、以及辞典里确实用来立目的异体，两个方向都要写：

```text
闲 st:閒    閒 st:闲
适 st:適    適 st:适
㑺 st:俊    俊 st:㑺
```

`闲 st:閒` 只把 `闲` 指向 `閒`，没有 `閒 st:闲`，反向的 `閒适 → 闲适` 就查不到；
`㑺` 在人名里有立目（`刘㑺`），所以输入 `刘俊` 时也要能展开过去。

只被辞典收过一次的冷僻异体则**只写正向**：

```text
𬸕 st:莺    （不写 莺 st:𬸕）
䴏 st:燕    （不写 燕 st:䴏）
```

因为 hunspell 在这里是检索辅助，负责「任意写法都能命中词典」；「某字有哪些
异体」是异体字字典的职责。`莺` 若反向展开到 `𬸕`，`莺莺燕燕` 的候选会从
4 涨到 81，多出来的全是查空的。判断标准在 `generate_zh_dic.py` 的
`composes()`：变体必须在多字词头里出现 ≥ 2 次，才保留反向行。

副作用是规范形可能不再单独出现在 `.dic` 里（例如 `spell("燕")` 会是 false）。
但 `燕` 本来就是词典词头，MDX 索引自身能命中；hunspell 在这里只负责补变体，
不承担「这个词存不存在」的判断。

词悦会逐字读这张表并组合，所以**混写不必进表**：

| 输入 | 展开出的写法（原样 + 5 个） |
| --- | --- |
| `闲适` | `闲适`、`閒適`\*、`閑适`、`閒适`、`闲適`、`閑適` |

\* 来自词级条目，见下。

## 词级条目：逐字转换不够时才写

```text
闲适 st:閒適
```

词级条目**先于**按字组合被读取，所以制表人指定的写法排在前面。它也是表达「非逐字
对应」映射的唯一方式：干/乾/幹、发/髮/發 这类分化，或繁体写法与简体字数不同的词。

单字表里没有的字无法展开——这是这张表的覆盖面边界。

## 同一个 head 多行为什么带 `/X`

一简对多繁（`发` → `發` / `髮`、`干` → `乾` / `幹` / `榦`）必须写成**同一个
head 的多行**：

```text
发/X st:發
发/X st:髮
```

`/X` 不是词缀规则，`zh_CN.aff` 里也没有定义它。它是用来绕过一个上游回归的。

Hunspell 1.7.3 的 [`f23fcd33`](https://github.com/hunspell/hunspell/commit/f23fcd33052c7c8a307eaa3e1b1a4c0cdcf45651)
（`ofz: Out-of-memory`）在 `HashMgr::add_word()` 里加了「同 head、无 affix flag
的一律当重复词跳过」的分支，却没比较 `HENTRY_DATA`（morph 描述）。于是
`发 st:發` / `发 st:髮` 两行只留第一行，`髮` 静默消失——`spell("发")` 仍是 true，
所以拼写检查这一侧完全看不出问题。1.7.2 及以前走 `next_homonym`，两行都保留。

带上任意一个 flag 就改回 `next_homonym` 分支；未定义的 flag 不产生派生词形，也不
影响 `spell()`（`hunspell -G` 只会吐出词本身）。已向上游报告：
[hunspell#1171](https://github.com/hunspell/hunspell/issues/1171)。

只有「一个 head 对应多个变体」的行才需要加，单值行不加。两个前提：

- `X` 必须在 `.aff` 里**保持未定义**——真给它写 `SFX` 规则就会开始派生词形；
- `FLAG` 不能是 `num`，否则 `X` 不是合法 flag，那两行会重新被合并掉。

标准 Hunspell（包括 GoldenDict-ng 用的系统库）都需要这个 flag。词悦自己 vendored
了 `hashmgr.cxx` 并放宽了去重条件，加不加都能拿到全部词干；等上游合并修复后，这里
可以改回不带 flag 的写法。

## 生成

需要 `pip install opencc-python-reimplemented`，以及 `mdict-utils`（处理 `.mdx`）。

### 0. 从词典目录生成词表

```bash
python3 build_words.py /path/to/词典目录 words.txt
```

扫 `.mdx` / `.dsl` / `.dsl.dz`，过滤掉句子和例句反查类词典，s2t 时保护 `CHAR_FIX`
里的类推简化字。已经有 `words.txt` 就跳过这一步。

### 1. 从词表生成全量表

```bash
python3 generate_zh_dic.py words.txt zh_CN_full.dic
# 可选：补进完全没有立目的生僻异体（只写正向 st:）
python3 generate_zh_dic.py words.txt zh_CN_full.dic /path/to/variants.json
```

`words.txt` 是一行一个词头（来自你实际使用的词典）。脚本用 OpenCC `t2s` 把每个词
归一化到简体，写正向行 `v st:std`；反向行只在 `v` 真的被辞典用来组词时才写
（见「单字条目」一节）。繁简相同的词没有变体，直接跳过。

单字条目不是单独维护的：中文词典的词表本身就收录单字词头，同一套逻辑自然会把
`閒 st:闲` 这类行产出来——而它们正是词悦能按字组合的前提。

#### OpenCC 不认的异体字

`t2s` 只认识它自己的字表。像 `㑺`（`俊` 的异体）、`㮣`（`概` 的异体）这类字，
`t2s` 原样返回，于是 `㑺` 和 `俊` 被当成两个不同的字，一行 `st:` 都不会生成。

补的依据是 ToyMDict 的 [`variants.json`](https://github.com/asgsdbrseg/ToyMDict)
（16,439 字 / 7,654 组），但它的口径是「异体字字典」，连带收通假与古今字，不能直接
灌进 `CHAR_FIX`。筛选标准：

- 只收**扩展区／兼容区 → BMP** 的组；
- 组内必须有一个 BMP 字**真的参与组词**（在词表的多字词头里出现过），用它当规范形；
- 两端都不在现有 `CHAR_FIX` 里，避免链式折叠。

按这个标准收了两批，共 511 对。没收的：

- 541 个整组都是生僻字（`𠌯` / `㒧`），组内找不到规范形，只能人工查书；
- 2,158 个落在 BMP 内部，多为 `人/入`、`一/壹/乙`、`大/太/泰` 这类形近或通假组，
  折了会把「大」的查询污染成「太」「泰」。

补完后，参与组词的字里有 `st:` 映射的比例从 69.6% 升到 76.5%。

#### 完全没有立目的异体字

第四个参数可以传一份异体字表（格式：字 → 该字所在的整组）。脚本会找出
**表里还没有正向行**、且组内有一个 BMP 字确实被辞典用来立目的扩展区异体，
补一条 `异体 st:规范形`，**不写反向行**。当前补进 893 条。

判据用「表里有没有这个字的正向行」而非「在不在词表」，因为只作为单字词头、
但 `t2s` 原样返回的字不会生成任何行。只补扩展区字，BMP 里的 `人/入`、
`大/太` 这类通假组不会被卷进来。

这些字在任何辞典里都没有立目（或只立单字、从不组词），所以只留正向没有损失：
电子书里复制到的生僻字能送到词典条目，而常用字一侧不会多出候选。不传这个
参数时，生成结果与之前完全一致。

### 2. 精简并发布

```bash
python3 prune_zh_dic.py zh_CN_full.dic zh_CN
```

第二条命令写出 `zh_CN.dic` / `zh_CN.aff`，也就是本仓库发布的那一对；`zh_CN_full.*`
留在本地（需要全量表的读取器可以直接用它）。

这一步删掉「两个读取器都能自己算出来」的词级条目：

- 词悦能用单字行逐字重建的；
- OpenCC 本来就会产出的。

其余保留：

```
1,264,295 条  →  35,073 条（33 MB → 676 KB）
  单字行保留    10,565
  词级行保留    24,508
    不能按字生成   1,256   （词悦补不了）
    OpenCC 补不了 23,252   （GoldenDict-ng 补不了）
```

脚本在写文件前会校验「源表每一条仍可推导」，写完后再校验一次输出文件，因此不会在
无声无息中丢掉候选。换 OpenCC 版本后重跑一次即可，几秒完成。

## 已知边界

- 只覆盖**单字表里出现过**的字；表里没有的字保持原样，不会自行发明映射。
- 只做**精确查找**：`st:` 映射整词，无法补全尚未输入的字，所以逐键建议不会展开异体。
- 逐字替换要求**字数相同**；字数不同的映射必须写成词级条目。
- 依赖 Hunspell 的 homonym 行为：1.7.3 起「同 head、无 flag」的行会被去重，本表用未定义的 `/X` 绕过，见上面的说明；上游修复后可去掉。
