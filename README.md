# hunspell_zh_CN

用于中文的 Hunspell 词形表，供**词悦**（Ciyue）和 **GoldenDict-ng** 做简繁与异体字通查。

中文没有词形变化，所以这里的 `st:` 干的是另一件事：记录**哪些字是同一个字的另一种
写法**。词悦会按字读这张表再组合，因此用一种写法输入的查询，能够命中用另一种写法建立的
词条；GoldenDict-ng 则把「一一对应」的部分交给 OpenCC，这张表只补它补不了的「[一简对多繁](https://ytenx.org/byohlyuk/KienxPyan)」问题。

## 文件

| 文件 | 大小 | 用于 |
| --- | --- | --- |
| `zh_CN.dic` | 32,308 条，约 626 KB | **词悦、GoldenDict-ng** |
| `zh_CN.aff` | 38 B | 与上面配对，空壳 |
| `build_words.py` | — | 从词典目录生成 `words.txt` |
| `generate_zh_dic.py` | — | 从词表生成**全量** `.dic` |
| `prune_zh_dic.py` | — | 把全量表精简成上面那份 |

本仓库发布的 `zh_CN.dic` 是**精简版**。全量表只是那几本词典词头的派生结果，谁手上有
那些词典都能自己生成；它也没必要全灌进词悦和 GoldenDict-ng——被删掉的那部分，两者都
能自己补上——所以不随仓库发布。既不按字组合、也不走 OpenCC 的读取器（例如 GoldenDict
Mobile）才需要它，请按下面的「生成」一节自行生成。

## 用法

**词悦**：设置 → Hunspell → 打开「启用词形还原与变体查找」→ 选择包含 `zh_CN.aff` 和
`zh_CN.dic` 的目录导入。

**GoldenDict-ng**：把这两个文件放进 Hunspell 目录，在「词典 → 词典来源 → Hunspell」中
加入该目录并启用。OpenCC 的简繁转换可以同时开启，两者互补。

## `zh_CN.aff`

```text
SET UTF-8
LANG zh
FLAG long
# 空壳
```

没有词缀规则，也没有复合词设置——Hunspell 此时就是一张「写法 → 各种写法」的哈希表，
这正是这里需要的全部。

## 单字条目：两个方向都要写

```text
闲 st:閒
闲 st:閑
閒 st:闲
閑 st:闲
适 st:適
適 st:适
```

两个方向缺一不可：`闲 st:閒` 只把 `闲` 指向 `閒`，没有 `閒 st:闲`，反向的
`閒适` → `闲适` 就查不到。

词悦会逐字读这张表并组合，所以**混写不必进表**：

| 输入 | 展开出的写法（原样 + 5 个） |
| --- | --- |
| `闲适` | `闲适`、`閒適`\*、`閑适`、`閒适`、`闲適`、`閑適` |

\* 来自词级条目，见下。

## 词级条目：逐字转换不够时才写

```text
闲适 st:閒適
```

词级条目**先于**按字组合被读取，所以制表人指定的写法排在前面。它也是表达「非逐字
对应」映射的唯一方式：干/乾/幹、发/髮/發 这类分化，或繁体写法与简体字数不同的词。

单字表里没有的字无法展开——这是这张表的覆盖面边界。

## 同一个 head 多行为什么带 `/X`

一简对多繁（`发` → `發` / `髮`、`干` → `乾` / `幹` / `榦`）必须写成**同一个
head 的多行**：

```text
发/X st:發
发/X st:髮
```

`/X` 不是词缀规则，`zh_CN.aff` 里也没有定义它。加它是因为 Hunspell **1.7.3 起**
的 `HashMgr::add_word()` 会把「同 head、无 affix flag」的第二行当重复词丢弃，
连 `st:` 一起丢（[hunspell#1171](https://github.com/hunspell/hunspell/issues/1171)）。
带上任意一个 flag 就改走 `next_homonym` 分支，两行都保留；未定义的 flag 不产生
派生词形，也不影响 `spell()`。

只有「一个 head 对应多个变体」的行才需要加，单值行不加。

## 生成

需要 `pip install opencc-python-reimplemented`，以及 `mdict-utils`（处理 `.mdx`）。

### 0. 从词典目录生成词表

```bash
python3 build_words.py /path/to/词典目录 words.txt
```

扫 `.mdx` / `.dsl` / `.dsl.dz`，过滤掉句子和例句反查类词典，s2t 时保护 `CHAR_FIX`
里的类推简化字。已经有 `words.txt` 就跳过这一步。

### 1. 从词表生成全量表

```bash
python3 generate_zh_dic.py words.txt zh_CN_full.dic
```

`words.txt` 是一行一个词头（来自你实际使用的词典）。脚本用 OpenCC `t2s` 把每个词
归一化到简体，然后为每一对写法**双向**各写一行。繁简相同的词没有变体，直接跳过。

单字条目不是单独维护的：中文词典的词表本身就收录单字词头，同一套逻辑自然会把
`閒 st:闲` 这类行产出来——而它们正是词悦能按字组合的前提。

### 2. 精简并发布

```bash
python3 prune_zh_dic.py zh_CN_full.dic zh_CN
```

第二条命令写出 `zh_CN.dic` / `zh_CN.aff`，也就是本仓库发布的那一对；`zh_CN_full.*`
留在本地（需要全量表的读取器可以直接用它）。

这一步删掉「两个读取器都能自己算出来」的词级条目：

- 词悦能用单字行逐字重建的；
- OpenCC 本来就会产出的。

其余保留：

```
1,262,576 条  →  32,308 条（33 MB → 626 KB）
  单字行保留    10,090
  词级行保留    22,218
    不能按字生成     714   （词悦补不了）
    OpenCC 补不了 21,504   （GoldenDict-ng 补不了）
```

脚本在写文件前会校验「源表每一条仍可推导」，写完后再校验一次输出文件，因此不会在
无声无息中丢掉候选。换 OpenCC 版本后重跑一次即可，几秒完成。

## 已知边界

- 只覆盖**单字表里出现过**的字；表里没有的字保持原样，不会自行发明映射。
- 只做**精确查找**：`st:` 映射整词，无法补全尚未输入的字，所以逐键建议不会展开异体。
- 逐字替换要求**字数相同**；字数不同的映射必须写成词级条目。
